# ADR-0004: push ペイロードにはメニュー本体を載せない

- 状態: 採用
- 日付: 2026-08-10

## 背景

08:00 JST に当日のメニューを iOS へプッシュ通知する。
ペイロードにメニュー本体を載せれば、オフラインでも通知だけで内容が読める。

## 決定

**push はトリガーと短い要約のみを運ぶ**。メニュー本体は 03:00 のバッチで Supabase に保存済み。
PWA は起動時に必ず Supabase から当日のメニューを読む。

**アプリ内に未読カウンタと通知履歴一覧を持たせる。**

## 理由

iOS の Web Push は信頼できない。

- 端末再起動後にリスナーが発火しないことがある
- 予期しない購読解除が起こる
- 通知を消したら内容は二度と読めない

通知が唯一の伝達経路になっていると、届かなかった日／消してしまった日にメニューが失われる。

**PWA を開けば同じ内容が見える**状態を常に保つ。

## silent push は使えない

`push` イベントで `showNotification()` を呼ばない push が数回続くと、iOS はサブスクリプションを
解除する。「裏でキャッシュだけ更新する」設計は取れない。
push でバックグラウンドコードを起動することもできない。

## 帰結

- 通知はオフラインでは要約しか読めない。これは許容する
- 未読カウンタと通知履歴一覧は iOS では**推奨ではなく必須**の作りになる
- 送信時に **404/410 が返ったら DB から購読を削除**し、**PWA 起動時に再購読**する処理を必ず入れる
- VAPID の `sub` は `mailto:...` または `https://...` にする。
  不正な形式だと Apple のプッシュサービスは 403 を返す
