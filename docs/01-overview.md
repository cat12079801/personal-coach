# 01. 概要

## 目的

Garmin Connect のアクティビティ記録と手動登録のワークアウト記録を集約して Web 上で閲覧し、
毎朝その日のトレーニングメニューを自動生成して通知する個人用アプリを作る。利用者は本人 1 人のみ。

マルチテナント・他人の資格情報の取り扱い・課金は一切考慮しない。

## 対象種目と記録方法

| 種目 | 記録方法 | 取得する内容 |
|---|---|---|
| ランニング（Garmin コーチのプラン含む） | Garmin で詳細計測 | サマリ + ラップ/スプリット |
| フィギュアスケート | Garmin で計測 | サマリのみ（詳細値は不要） |
| ボルダリング | Garmin で計測 | サマリのみ |
| 腕立て伏せ等の筋トレ | アプリで手動登録 | 自前スキーマ |
| 歩行 | — | **取り込まない**（日常的な活動でありトレーニングとして扱わない） |

> ボルダリングは当初アプリで手動登録する想定だったが、Garmin Connect 側で記録する方針に
> 変更した（2026-08-11）。手動ログのテーブルは
> [0004](../supabase/migrations/0004_drop_bouldering_logs.sql) で削除済み。

## 自動化要件

- **03:00 JST** — 前日までのアクティビティを取り込み、当日のメニューを生成して DB に保存
- **08:00 JST** — 生成済みメニューを iOS へプッシュ通知

## メニュー生成ルール

ルールベースで実装する。**LLM は使わない。**

1. Garmin コーチのランニングプランを最優先し、その内容は改変しない
2. スケートの予定有無は Google カレンダーを参照して判定する
3. ランがポイント練習の日は筋トレを入れない、休養/イージーの日は筋トレを差し込む
4. スケート予定がある日は筋トレを削り、翌日の強度を下げる
5. Garmin の `training_readiness` が低い日は全体の強度を 1 段下げる

ルール 1 の「Garmin コーチのプラン」をどの API から取れるかが唯一の未知であり、
ここでメニュー生成ロジックの入力形状が決まる。[06-poc-notes.md](06-poc-notes.md) を参照。

## 心拍の扱いに関する注意

- **ボルダリングの手首光学式心拍は信用できない。** ホールドを握る動作で前腕が緊張し、
  腕を上げた状態が続くため。心拍ベースの負荷指標にボルダリングを混ぜないこと。
  Garmin から取り込むようになったぶん、取り込み側で明示的に除外する必要がある
- **フィギュアも平均心拍が実感より低く出る。** 滑走と休憩の繰り返しのため
- **RPE を入れるのはランのみ。** 全種目に入れるのは手間に見合わないため。
  結果としてクライミング系とスケートには負荷指標が無い（心拍も RPE も使えない）。
  これらは「記録するが負荷は評価しない」種目として扱う
- **ランは Garmin の Training Load / Training Effect をそのまま使う**
