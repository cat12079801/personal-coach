# 01. 概要

## 目的

Garmin Connect のアクティビティ記録と手動登録のワークアウト記録を集約して Web 上で閲覧し、
毎朝その日のトレーニングメニューを自動生成して通知する個人用アプリを作る。利用者は本人 1 人のみ。

マルチテナント・他人の資格情報の取り扱い・課金は一切考慮しない。

## 対象種目と記録方法

| 種目 | 記録方法 | 取得する内容 |
|---|---|---|
| ランニング（Garmin コーチのプラン含む） | Garmin で詳細計測 | サマリ + ラップ/スプリット |
| フィギュアスケート | Garmin で計測 | **サマリのみ**（時間と消費カロリーが分かれば十分。要素は書かない） |
| ボルダリング | Garmin で計測 | サマリのみ |
| 腕立て伏せ等の筋トレ | アプリで手動登録 | 自前スキーマ |
| 歩行 | — | **取り込まない**（日常的な活動でありトレーニングとして扱わない） |

> ボルダリングは当初アプリで手動登録する想定だったが、Garmin Connect 側で記録する方針に
> 変更した（2026-08-11）。手動ログのテーブルは
> [0004](../supabase/migrations/0004_drop_bouldering_logs.sql) で削除済み。
>
> スケートも同じく手動ログをやめた（2026-08-13）。`skating_logs` と未紐付け一覧は
> [0008](../supabase/migrations/0008_drop_skating_logs_and_unlinked.sql) で削除済み。
> **ウォッチの付け忘れは Garmin Connect 側で手動記録する。** アプリ側で欠測を埋めない。

## 自動化要件

- **03:00 JST** — 前日までのアクティビティを取り込み、当日のメニューを生成して DB に保存
- **08:00 JST** — 生成済みメニューを iOS へプッシュ通知

## メニュー生成ルール

ルールベースで実装する。**LLM は使わない。**

出力は 3 段構成。

```
今日のメニュー
├── ラン          ← Garmin のプランをそのまま
├── 補強(Garmin)  ← Garmin が置いた筋トレ。そのまま
└── 独自筋トレ     ← アプリが足す。上半身・スキル系
```

**R1. Garmin のプランは改変しない。** 絶対条件。

**R2. 独自筋トレを置く日は 休養日 > ポイント練習でない日 > ポイント練習日 の優先度で選ぶ。**
Garmin の補強がある日に重ねてよい。`taskList` が 7 日先まで返るので、その週の残りを
先読みして決める（手前から貪欲に置くと直後の休養日を取り逃がすため）。

**R3. `training_readiness` が低い日はセット数を減らす。** 段階は下げない。
`level` が LOW / VERY_LOW、または `score < 50`。`validSleep: false` の日は下げない。
**ランには手を入れない**（R1）。

**R4. 週あたりの実施回数の下限を確保する。** 既定は週 2 回・中 1 日以上。

実装は [batch/src/personal_coach/menu/rules.py](../batch/src/personal_coach/menu/rules.py)。
2026-08-12 に本人レビュー済み。

### 廃止したルール

当初あった以下の 2 つは廃止した。

- 「スケート予定がある日は筋トレを削る」→ **両立してよい**。
  むしろ「ランが休養日でスケートする日」は筋トレを置くべき日になる
- 「スケートの翌日は強度を下げる」→ **不要**

カレンダーの予定は**表示用としてメニューに載せる**。「今日やることを 1 画面で確認する」
ためのものであり、**ルールの判定には一切使わない**。

## 心拍の扱いに関する注意

- **ボルダリングの手首光学式心拍は信用できない。** ホールドを握る動作で前腕が緊張し、
  腕を上げた状態が続くため。心拍ベースの負荷指標にボルダリングを混ぜないこと。
  Garmin から取り込むようになったぶん、取り込み側で明示的に除外する必要がある
- **フィギュアも平均心拍が実感より低く出る。** 滑走と休憩の繰り返しのため
- **RPE を入れるのはランのみ。** 全種目に入れるのは手間に見合わないため。
  結果としてクライミング系とスケートには負荷指標が無い（心拍も RPE も使えない）。
  これらは「記録するが負荷は評価しない」種目として扱う
- **ランは Garmin の Training Load / Training Effect をそのまま使う**
